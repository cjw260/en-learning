**Input**: User description: "为 en-learning-plus 定义一个基于现有认证、词典、课程、单词学习和 AI 对话能力的个性化英语学习 Coach，形成讲解、练习、批改、学习记录更新、复习安排和下一步推荐的安全闭环。"

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 获得个性化讲解与纠错 (Priority: P1)

已登录学习者向 Coach 询问单词、语法、句子纠错或学习方法。Coach 只读取完成本次任务所需的本人学习数据，并依据可获得的英语水平、已学词汇、薄弱项、历史错误、近期表现、当前课程或学习目标调整解释难度、例句和建议。若画像数据缺失，Coach 明确说明个性化依据有限，不伪造学习历史。

**Why this priority**: 这是 Coach 区别于现有通用问答的核心用户价值，也是后续练习和复习闭环的入口。

**Independent Test**: 使用两个问题相同但等级和学习历史不同的测试用户发起请求；验证两者均得到结构有效、来源受控且难度或例句明显不同的回答，且彼此数据不混用。

**Acceptance Scenarios**:

1. **Given** 已登录用户有可用的等级、已学词汇和错误记录，**When** 用户要求纠正英文句子，**Then** Coach 返回纠正结果、适合该等级的解释、示例、错误分类、下一步行动和可核验引用。
2. **Given** 两名用户提出相同问题但学习画像不同，**When** Coach 分别回答，**Then** 回答在词汇难度、解释深度、示例或建议中的至少一个方面体现画像差异，且不出现另一用户的数据。
3. **Given** 当前用户缺少等级、错题或近期表现，**When** 用户提问，**Then** Coach 使用现有可用数据提供受限个性化回答，并明确哪些建议基于通用规则，不虚构缺失数据。
4. **Given** 未登录访问者或持无效令牌的请求，**When** 其调用 Coach 或读取 Coach 历史，**Then** 请求在读取任何学习数据或调用外部模型前被拒绝。
5. **Given** 用户在 Prompt、请求体或工具参数中加入其他用户的标识，**When** Coach 处理请求，**Then** 这些标识不改变服务端认证主体，访问被限制在当前登录用户。

### User Story 2 - 生成针对性练习 (Priority: P1)

已登录学习者可以要求选择题、填空题、翻译题或情境对话。Coach 基于本人等级、薄弱项、到期复习词、近期错误和当前学习目标生成适量练习，并在向用户展示的内容中隐藏标准答案和内部评分依据。

**Why this priority**: 针对性练习把解释转化为可检验的学习行为，是形成个性化闭环的必要环节。

**Independent Test**: 为具有不同薄弱词汇和错误类型的测试用户请求同一题型；验证题型、数量和难度合法，内容分别覆盖各自薄弱项，且不存在未学内容的不合理突袭或答案泄露。

**Acceptance Scenarios**:

1. **Given** 用户有到期复习词和近期语法错误，**When** 用户要求混合练习，**Then** Coach 从允许的四类题型中生成与其等级和薄弱项相关的题目，并说明本组练习的选择依据。
2. **Given** 用户指定题型和主题，**When** 该请求在允许范围内，**Then** Coach 遵守题型要求并只使用可访问的学习材料。
3. **Given** 用户要求使用尚未学过且明显超出其等级的内容，**When** Coach 生成练习，**Then** Coach 降低难度、先提供必要提示或说明该内容属于挑战项，而不是把它当作已掌握知识。
4. **Given** 相关学习材料服务不可用或没有匹配内容，**When** 用户请求练习，**Then** Coach 返回结构有效的降级结果，说明无法可靠生成，不伪造引用，也不创建可提交的无依据练习。

### User Story 3 - 批改并形成学习闭环 (Priority: P1)

学习者提交练习答案后，Coach 对答案进行结构化批改，提供分数、纠正、解释、示例和错误分类。只有批改结果通过校验且题目、答案和资源均属于当前用户时，系统才保存一次作答，并原子地更新相应学习状态和下次复习时间。

**Why this priority**: 批改和可靠写入决定了 Coach 是否能把一次对话转化为持续有效的学习数据。

**Independent Test**: 对同一练习提交正确、错误、重复和越权答案；验证有效答案获得完整批改并只保存一次，无效或越权答案不产生任何学习状态变化。

**Acceptance Scenarios**:

1. **Given** 当前用户提交本人未批改练习的完整答案，**When** 批改通过结构和业务校验，**Then** 返回 0 至 100 的分数、纠正说明、错误类型、示例、下一步行动，并允许保存。
2. **Given** 批改输出缺字段、类型错误、分数越界或引用无效，**When** 校验失败，**Then** 该输出不会发送为最终结果，也不会触发作答保存或掌握度更新。
3. **Given** 有效批改已完成，**When** 保存作答，**Then** 作答记录与掌握度/复习时间变更全部成功或全部失败，用户能看到发生的学习状态变化。
4. **Given** 同一逻辑提交因双击、网络重试或流重连被重复发送，**When** 保存操作再次到达，**Then** 系统返回首次操作的结果，不新增记录、不重复更新掌握度。
5. **Given** 用户提交其他用户的练习标识或作答标识，**When** 批改或保存，**Then** 请求被拒绝且不泄露目标资源是否存在。

### User Story 4 - 控制流式会话 (Priority: P2)

学习者在界面中看到连接、分析、获取学习信息、生成、批改、保存、完成、取消、超时和失败等友好状态，以及逐步生成的可展示内容。用户可以取消仍在执行的请求，也可以在安全条件下重试。

**Why this priority**: 可见进度和可靠控制降低长响应的不确定感，并避免重试导致重复写入。

**Independent Test**: 分别模拟正常生成、主动取消、网络中断、模型超时、工具失败和断线重连；验证界面状态明确、敏感内部信息不泄露，并且写入保持幂等。

**Acceptance Scenarios**:

1. **Given** Coach 请求正常执行，**When** 工作流推进，**Then** 前端按顺序显示用户可理解的状态和增量内容，最终只接收一个通过 Schema 校验的完成结果。
2. **Given** 用户在生成或只读工具执行期间取消，**When** 取消被服务端确认，**Then** 下游工作尽快中止，不再触发新的写操作，并显示“已取消”。
3. **Given** 网络在最终写入前中断，**When** 用户重试或重连，**Then** 系统恢复或重新执行安全步骤，不重复保存学习记录。
4. **Given** 模型、工具或数据源失败，**When** 无法继续完成当前意图，**Then** 前端收到结构化、可操作的错误或降级结果，而不是内部 Prompt、原始堆栈或密钥信息。

### User Story 5 - 理解推荐和学习变化 (Priority: P2)

学习者完成问答或练习后，能够知道 Coach 为什么推荐“复习”“练习”或“继续”，以及本次有效练习使哪些词汇或知识点的状态发生了变化。

**Why this priority**: 可解释的推荐让用户信任个性化结果，也便于发现画像或批改不合理的问题。

**Independent Test**: 完成一次含正确和错误答案的练习；验证下一步建议可追溯到本次表现或到期计划，且页面明确展示保存前后变化。

**Acceptance Scenarios**:

1. **Given** 用户在到期词汇上表现较差，**When** 本次作答有效保存，**Then** `nextAction` 为合理行动，解释引用本次表现或复习状态，并展示相应学习状态变化。
2. **Given** 用户表现良好且没有紧急复习项，**When** Coach 推荐继续学习，**Then** 推荐说明依据，不声称不存在的弱项。
3. **Given** 批改成功但保存失败，**When** 最终结果返回，**Then** 用户仍可查看批改，但界面明确标记“学习状态未更新”并允许安全重试保存。

### User Story 6 - 评估和追踪 Coach 质量 (Priority: P2)

产品和工程团队可以使用脱敏、可重复运行的离线样本验证 Coach 的纠错、难度适配、练习针对性、工具调用、安全、结构化输出、引用、失败降级、延迟和成本；每次线上请求也可通过统一 Trace 关联模型、Prompt、工具和用户反馈。

**Why this priority**: 没有持续评测和可观测性，就无法判断个性化是否真实有效，也无法安全升级 Prompt 或模型。

**Independent Test**: 运行一个 50 至 100 条的版本化评测集，并抽查对应线上 Trace；验证确定性安全门槛、质量评分、延迟/Token 数据和反馈关联均可复现。

**Acceptance Scenarios**:

1. **Given** Prompt、模型或结构化 Schema 版本发生变化，**When** 候选版本进入发布评审，**Then** 完整离线回归集先运行，严重安全回归或明显质量回退会阻止发布。
2. **Given** 一次线上 Coach 请求完成、取消、超时或失败，**When** 授权运维人员按 Trace 查询，**Then** 能看到规定的版本、时延、Token、工具顺序、校验和结果状态，但看不到 JWT、API Key 或不必要的隐私原文。
3. **Given** 用户对结果提供反馈，**When** 反馈被记录，**Then** 反馈可关联到脱敏 Trace、Prompt/模型版本和输出类型，用于后续评测样本筛选。

### Edge Cases

- 用户从未学习任何单词、没有购买课程、没有等级或历史错误时，Coach 只能基于当前问题和公开词典数据回答，并标记个性化依据不足。
- 当前只有 `isMaster` 布尔状态而没有掌握度或复习时间时，Coach 不得把“已掌握”解释成可用于间隔复习的完整掌握模型。
- 项目中的 `ErrorEntry` 是技术错误遥测，不得当作学习者错题或语法错误使用。
- 用户有已学单词但其中部分词典记录被删除、不可见或与当前课程不再关联时，工具应跳过无效关联并记录数据完整性状态。
- 用户请求的语法材料在第一版数据源中不存在时，搜索返回“无可靠材料”，不能伪造课程、引用或语法知识库命中。
- 题型不在选择题、填空题、翻译题、情境对话之内，或题量、输入长度超限时，请求在模型调用前被拒绝或规范化为用户可确认的合法范围。
- 用户提交空答案、部分答案、重复题目答案、超长答案、恶意脚本或与练习不匹配的答案时，输入校验失败，不触发写入。
- 选择题不得把标准答案放在流式增量、引用或工具状态中；批改前也不得泄露隐藏评分依据。
- 同一会话同时发起多个练习或多个保存请求时，各自状态和幂等键必须隔离，不能串题或交叉更新。
- Prompt Injection 要求忽略规则、显示系统 Prompt、调用未授权工具、访问任意 `userId` 或修改其他用户数据时，系统拒绝相关指令并继续安全回答或终止请求。
- JWT 在长连接期间过期、被撤销或身份上下文丢失时，后续读取和写入均不得继续；前端收到重新认证提示。
- 用户取消发生在写事务提交边界时，系统必须能明确返回“未保存”或“已保存一次”的可查询状态，不能处于未知的部分写入状态。
- SSE 重连丢失部分事件时，客户端不得把未校验的增量拼接成最终结果；最终结构化结果以服务端确认的完成事件为准。
- 模型在内容上答对但结构不符合 Schema，或结构合法但引用不支持结论时，均不得直接成为可保存的最终批改。
- 一个只读工具失败时，工作流只能在不降低事实可靠性和权限边界的前提下降级；写工具失败时不得用推测结果补写。
- 工具循环、模型反复请求同一工具或预算耗尽时，工作流停止并返回明确的预算错误。
- 外部模型返回敏感内容、内部推理、Prompt 片段或工具参数时，服务端必须过滤或拒绝，而不是透传。
- 删除会话或学习数据的请求与正在执行的 Coach 请求并发时，删除后的数据不得被再次写回或重新出现在历史中。

## Requirements *(mandatory)*

### Existing Capability Baseline

以下基线来自 2026-09-02 对 `en-learning-plus` 当前代码的只读审查，是本规格的事实边界：

| Area | Existing capability | Confirmed gap relevant to this feature |
|------|---------------------|----------------------------------------|
| Authentication | 主服务已有 JWT 签发、刷新和 `AuthGuard`，受保护学习接口从 `req.user.userId` 读取身份。 | AI 的对话和历史接口未应用服务端认证；AI 前端请求未携带 Authorization，且请求体/查询参数直接传 `userId`。 |
| Learner profile | `User` 有用户名、联系信息、简介、累计单词数和打卡天数。 | 没有英语水平、学习目标、当前学习课程、薄弱知识、主要错误类型或近期练习表现字段。 |
| Vocabulary | `WordBook` 提供词条、释义、翻译、词性、考试标签和频率；`WordBookService` 支持词和考试标签搜索。 | 没有学习材料统一引用合同，也没有语法材料或课程正文数据。 |
| Course learning | `Course`、购买记录和本人已购课程查询存在；`LearnService` 可向已购课程用户返回 10 个尚无记录的词。 | 当前课程只代表词汇集合；没有通用课程课时、语法知识点或学习目标进度。 |
| Word progress | `WordBookRecord` 按用户和单词唯一，只有 `isMaster` 与时间戳；现有流程完成一组拼写后批量标记掌握并增加计数。 | 没有逐题作答、错误类型、分数、掌握度、复习间隔、下次复习时间或到期词能力；现有批量保存也未定义重试幂等行为。 |
| Error records | 有 `ErrorEntry`。 | 该实体记录 JavaScript/Promise 等技术错误和堆栈，不是学习错题，严禁用于学习画像。 |
| AI chat | 独立 AI 应用使用现有对话/推理模型、角色 Prompt、流式文本和 PostgreSQL 会话检查点；通用问答可选网络搜索。 | 输出是自由文本；无受控学习工作流、Coach 工具、业务 Schema、个性化学习数据、取消控制、用户级限流、成本预算或完整 Trace。现有聊天流还会展示原始 reasoning 内容。 |
| Existing AI tool | 每日摘要中存在一个按模型传入 `userId` 直接查询数据库的工具。 | 该工具绕过当前请求的认证主体和业务 Service，不满足 Coach 工具权限要求，不能按原样复用。 |
| Evaluation and tests | 未发现 Coach/AI 离线评测集或现有单元、集成和端到端测试。 | 所有质量、安全、延迟和成本门槛都需先建立可复现基线。 |

本表未列出的能力不得被后续阶段视为已实现。

### Functional Requirements

#### Controlled Learning Workflow

- **FR-001**: Coach MUST 仅向已通过服务端 JWT 验证的用户开放；对话创建、流式响应、历史读取、重试、取消、批改和保存均属于受保护操作。
- **FR-002**: 每个请求 MUST 经过可追踪的受控步骤：识别意图 → 获取当前用户必要画像 → 获取相关学习内容 → 生成讲解或练习 → 在用户提交答案时批改 → 在有效批改后保存 → 推荐下一步行动。
- **FR-003**: 工作流 MUST 根据意图区分“普通问答/讲解”“句子纠错”“生成练习”“答案批改”“复习推荐”；不适用的步骤 MUST 被明确跳过而不是伪造执行。
- **FR-004**: 工作流 MUST 支持多轮交互并保存用户隔离的会话、当前练习、待批改答案、最近有效批改和写入状态；状态不得仅依赖前端传回的自由文本。
- **FR-005**: 每个步骤 MUST 有唯一顺序、开始/结束状态、耗时、结果状态和错误状态，且能通过同一 Trace 关联。
- **FR-006**: 模型只能在工作流允许的当前步骤选择允许的工具；模型请求越级保存、重复保存、调用未注册工具或绕过批改门禁时 MUST 被拒绝。
- **FR-007**: 只有 `grade_answer` 返回通过输入、归属、业务和输出校验的有效批改后，工作流才可进入 `save_attempt`。
- **FR-008**: 推荐步骤 MUST 使用本次有效结果、当前到期内容和画像依据生成 `review`、`practice` 或 `continue`，并提供用户可理解的理由。
- **FR-009**: 任何部分失败 MUST 保留已确认的只读/生成结果，但不得产生不完整学习写入；写入必须全成或全败。
- **FR-010**: 工作流 MUST 有明确的终止状态：完成、用户取消、超时、预算终止、认证失败、校验失败、依赖失败或安全拒绝。

#### Personalization

- **FR-011**: 个性化决策 MUST 在数据可用时考虑英语水平、已学/未学词汇、到期复习词、历史错题及错误类型、近期练习表现、当前课程和学习目标。
- **FR-012**: Coach MUST 对每个使用的个性化信号标明来源状态：可用、缺失、过期或不适用；缺失信号不得被模型推测成事实。
- **FR-013**: 相同请求面对不同等级或学习历史时，回答或练习 MUST 在难度、词汇选择、解释深度、示例、题型组合或下一步建议中体现与信号一致的差异。
- **FR-014**: Coach MUST 区分已学、未学和状态未知的词；未学词可以作为有提示的挑战内容，但不得被陈述为用户已掌握。
- **FR-015**: 第一版英语水平 MUST 采用用户可查看和编辑的 CEFR `A1`–`C2` 自报等级，并记录来源为 `USER_DECLARED`；学习目标可由用户设置，可选当前课程必须属于本人已购课程。近期表现只能在当前请求内进行有界难度适配，不得静默修改用户声明等级。未设置等级时必须标记画像不足，不得假设默认等级。

#### Identity, Authorization, and Validation

- **FR-016**: 用户身份 MUST 只来源于当前请求经验证的服务端认证上下文；前端字段、Prompt、模型输出、会话历史和工具参数中的任何 `userId` MUST 被忽略或拒绝。
- **FR-017**: Coach 面向模型的工具输入 Schema MUST 不包含可选择用户身份的字段；经验证的身份作为不可由模型修改的执行上下文传递。
- **FR-018**: 用户只能读取和修改属于本人的学习画像、课程权限、练习、作答、复习计划、会话和反馈；公共词典/课程元数据仍须经过允许的数据范围返回。
- **FR-019**: 所有资源标识在使用前 MUST 再次验证存在性、当前用户归属、课程访问权、状态有效性和与当前工作流的关联；越权响应不得泄露资源是否属于其他用户。
- **FR-020**: 所有工具输入、工具结构化输出、最终模型输出和流式完成事件 MUST 由版本化 Zod 或 JSON Schema 合同校验。
- **FR-021**: 无效参数、未知字段、越界值、非法枚举、超长文本、无效引用、无效模型输出和权限失败 MUST 被拒绝并记录安全的错误分类。
- **FR-022**: `save_attempt` 等写操作 MUST 在业务代码中重新执行身份、资源归属、前置批改、参数、状态转换和幂等性校验，不能信任先前模型判断。
- **FR-023**: 工具 MUST 通过现有业务 Service 使用已有能力；若现有 Service 不支持所需的画像、作答、掌握度或复习能力，后续阶段 MUST 先扩展明确的业务 Service 合同。工具自身不得直接进行不受控数据库读写。
- **FR-024**: 现有每日摘要的直接数据库查询工具 MUST NOT 作为 Coach 授权模式的依据或直接复用，除非其后续被改为认证主体固定、业务 Service 受控且 Schema 完整的合同。

#### Learning Tool Contracts

所有工具共享以下合同：执行主体来自服务端认证上下文；输入和输出均有 `schemaVersion`；每次调用属于一个 Trace 和工作流步骤；结果只含当前任务所需的最少数据；失败返回稳定错误类别和是否可重试；不得返回密钥、JWT、系统 Prompt、数据库错误、内部堆栈或其他用户数据。

| Tool | Access | Business responsibility | Validated input (excluding server auth context) | Validated output | Permission and preconditions | Failure behavior |
|------|--------|-------------------------|-------------------------------------------------|------------------|------------------------------|------------------|
| `get_learner_profile` | Read-only | 汇总当前用户完成本次请求所需的等级、学习目标、已学/未学概况、薄弱词/知识点、主要错误类型、近期表现和当前课程。 | 可选的任务范围；允许的画像维度；每维度结果上限。不得接受 `userId`。 | 画像快照、各信号来源/新鲜度、数据完整性标记和快照时间；不得返回联系信息、密码、令牌或无关个人资料。 | 必须已登录；只能读取认证主体；课程相关信息需满足本人访问权。 | 无历史返回合法的“数据不足”快照；依赖失败返回可重试/不可重试状态，不补造画像。 |

- **FR-025**: 只读或计算工具不得改变学习记录、掌握度、复习时间或累计学习计数；创建暂存练习不能被统计为完成练习。
- **FR-026**: `save_attempt` 是第一版唯一允许由 Coach 工作流触发的学习数据写工具；模型不得调用删除、课程修改、用户修改或其他高风险操作。
- **FR-027**: 工具调用次数、单次/总耗时和重试次数 MUST 受请求预算约束；同一参数的重复只读调用应被工作流识别，避免无界循环。
- **FR-028**: `search_learning_materials` 的业务合同 MUST 与具体检索提供者解耦，并以稳定材料标识和 `Citation` 返回结果，使后续替换为 pgvector RAG 时不改变 Coach 的业务语义；第一版不包含向量知识库或摄取流水线。

#### Structured Result Contract

最终完成结果 MUST 是版本化、类型安全的对象，至少包含：

```text
schemaVersion: string
responseType: "answer" | "correction" | "exercise" | "grading" | "recommendation" | "degraded"
correction: string
explanation: string
examples: string[]
errorTypes: string[]
score: number | null
nextAction: "review" | "practice" | "continue"
citations: Citation[]
nextActionReason: string
traceId: string
exercise?: ExerciseForLearner
learningUpdate?: LearningUpdate
```

字段规则：

| Field | Meaning and constraints | Required behavior |
|-------|-------------------------|-------------------|
| `schemaVersion` | 非空、受支持的合同版本。 | 始终必填；未知版本不得由前端按已知类型展示。 |
| `responseType` | 当前最终结果的唯一主场景。 | 始终必填；必须与工作流意图和可选对象一致。 |
| `correction` | 对用户原句或答案的建议正确表达；不适用时为空字符串。 | 纠错和批改有可纠正内容时非空；普通问答/练习生成可为空。 |
| `explanation` | 面向学习者、与其可用等级相符的主要讲解或结果摘要。 | 始终为非空安全文本；不得包含内部推理、Prompt 或堆栈。 |
| `examples` | 支持讲解或纠错的去重示例。 | 始终为数组；无可靠示例时可为空；每项必须在长度预算内。 |
| `errorTypes` | 规范化错误类别集合，例如词汇、拼写、语法、时态、冠词、介词、搭配、语序、表达、理解或 `other`。 | 无错误时为空；未知类型映射为 `other` 并保留安全说明，不能接收任意可执行值。 |
| `score` | 本次可评分答案的整数总分，范围 0–100。 | 只有有效批改为数字；普通问答、纠错、练习生成、推荐和不可评分降级为 `null`。 |
| `nextAction` | 下一步学习动作。 | 始终为枚举之一，并由 `nextActionReason` 解释。 |
| `citations` | 支持回答、练习或批改的材料引用。 | 始终为数组；引用必须来自本次已验证材料结果；无材料时为空且不得暗示有来源。 |
| `nextActionReason` | 用户可理解的推荐依据。 | 始终非空，引用本次表现、到期计划或明确的通用依据。 |
| `traceId` | 用于支持和反馈关联的非敏感请求标识。 | 始终必填；不得编码原始用户标识或密钥。 |
| `exercise` | 可提交的用户版练习，含练习标识、题型、说明和题目，不含答案键。 | 仅 `responseType=exercise` 时必填；其他场景不得误带可提交练习。 |
| `learningUpdate` | 本次保存的作答及学习状态变化，含是否保存、重放或未保存。 | 有保存尝试时必填；批改未保存时必须明确 `not_saved`，不能暗示已更新。 |

`Citation` MUST 至少包含稳定材料标识、材料类型 `word|course|grammar`、显示标题和支持的结论/题目范围；可选定位信息只能指向用户有权访问的内容。生成示例、模型常识、Prompt 文本和其他用户记录不得伪装为引用。

场景差异：

| Scenario | `correction` | `explanation` | `examples` / `errorTypes` | `score` | `nextAction` | Additional object |
|----------|--------------|---------------|---------------------------|---------|--------------|-------------------|
| 普通问答/学习方法 | 通常为空 | 主要回答，按可用等级适配 | 示例可选；错误类型通常为空 | `null` | 根据当前画像选择 | 无 |
| 句子纠错 | 修正后的表达 | 解释原句问题及改法 | 至少在需要时给示例和错误分类 | `null` | 通常为练习或继续，由证据决定 | 无 |
| 练习生成 | 为空 | 说明练习目标和个性化依据 | 可含示例；错误类型为目标弱项而非本次错误时必须明确语义 | `null` | `practice` | `exercise` 必填 |
| 答案批改 | 有错误时给修正；全对时可为空 | 总结与逐项解释 | 与实际错误一致；全对可为空 | 0–100 | 依据表现选择 | `learningUpdate` 表明保存状态 |
| 复习推荐 | 为空 | 概述推荐原因 | 可含例句；错误类型只来自已验证历史 | `null` | 通常为 `review`，但由状态决定 | 无 |
| 降级 | 为空或仅包含确定性安全修正 | 明确说明不可用能力和可行下一步 | 不得编造 | `null` | 选择仍可执行的安全动作 | 不得含伪造练习/更新 |

- **FR-029**: 模型输出首次不符合 Schema 时，系统 MUST 在剩余预算内进行一次受控的结构重试；仅对可确定修复的语法/封装问题可再进行一次不改变语义的确定性修复。
- **FR-030**: 经过受控重试/修复仍无效的输出 MUST 被拒绝；系统返回由业务代码生成的合法降级对象。批改降级不得给出可保存分数。
- **FR-031**: 未经完整 Schema、引用、权限和场景一致性校验的内容只能作为临时流式文本，不得成为最终结果、评分或写入依据。
- **FR-032**: 前端 MUST 依据共享的版本化类型合同渲染字段，并对未知版本、缺失字段或未知事件进入失败/升级提示，不使用松散自由文本猜测结构。

#### Streaming, Cancellation, and Retry

- **FR-033**: 现有 Vue 前端 MUST 通过 SSE 提供 Coach 流式体验，并区分 `connected`、`status`、`content_delta`、`tool_status`、`result`、`completed`、`cancelled` 和 `error` 等用户可判定事件。
- **FR-034**: `status` 与 `tool_status` 只能显示“正在分析问题”“正在读取你的学习进度”“正在生成练习”“正在批改”“正在保存学习进度”等友好描述，不得展示工具原始参数、数据库查询、系统 Prompt、内部推理链或敏感信息。
- **FR-035**: `content_delta` 只用于渐进显示，不视为可解析最终结果；唯一的 `result` 事件必须携带已通过全部校验的结构化结果，`completed` 确认本次流结束。
- **FR-036**: 每个事件 MUST 具备请求内可排序标识；重连或重复事件不会导致前端重复拼接最终结果或重复触发写操作。
- **FR-037**: 用户 MUST 能取消尚未结束的请求；服务端收到取消后停止新的模型和工具调用并中断可中断下游请求。
- **FR-038**: 取消发生在写入前时不得保存；写入已原子提交时取消不能回滚成未知状态，重试查询必须返回“已保存一次”的结果。
- **FR-039**: 网络中断、模型失败或可重试工具失败后，前端 MUST 提供安全重试；重试复用逻辑请求身份和写幂等语义，但不得信任客户端声称的先前步骤结果。
- **FR-040**: 认证失败、越权、无效输入和不可重试业务冲突不得自动重试；界面必须给出可操作但不泄露内部信息的提示。

#### Request Governance and Failure Handling

- **FR-041**: Coach MUST 按认证用户执行频率和并发限制；未认证来源还必须在认证前受到基础滥用保护。
- **FR-042**: 每个请求 MUST 有可配置且在发布前批准的输入 Token、输出 Token、费用、工具调用次数、单工具耗时、总执行时间和重试预算。
- **FR-043**: 预算在执行前预计必然超出或执行中已经耗尽时，工作流 MUST 安全停止，返回明确预算类别，不开始新的工具或写操作。
- **FR-044**: 超时和取消 MUST 传播至模型和可中断的下游数据调用；超时后迟到结果不得再次写入或推送为最终结果。
- **FR-045**: 依赖失败分类至少包括认证/权限、输入校验、Schema、资料不可用、模型不可用、工具超时、总超时、预算、冲突和内部错误；每类均须定义可重试性和用户文案。
- **FR-046**: 模型不可用时可返回不依赖模型的安全状态或现有材料摘要；无法可靠批改或生成时必须承认失败，不得伪造分数、引用或学习更新。
- **FR-047**: 所有写操作 MUST 使用由服务端认可的幂等键和状态机；幂等范围至少区分用户、逻辑练习、答案版本和写操作。
- **FR-048**: 任何重试、SSE 重连、重复提交、进程重启或迟到回调均不得为同一逻辑作答创建第二条记录或再次调整学习状态。

#### Observability

- **FR-049**: 每次 Coach 请求 MUST 生成统一 Trace，覆盖入口、工作流步骤、模型调用、工具调用、Schema 校验、流式完成、取消/超时、写入和用户反馈。
- **FR-050**: Trace MUST 记录 Prompt 标识及版本、模型提供者/名称/版本、首字响应时间（TTFT）、完整响应耗时、输入/输出 Token、估算费用、工具名称/顺序/耗时/结果状态、Schema 失败与重试次数、降级、取消、超时、异常和最终结果类型。
- **FR-051**: Trace 中的用户标识 MUST 使用内部不可逆或不可直接反查的脱敏标识；资源标识和内容只保留排障/评测所需的最小范围。
- **FR-052**: 日志、Trace、流式事件和错误响应 MUST NOT 记录或返回 JWT、刷新令牌、API Key、数据库凭证、系统 Prompt、内部推理、完整错误堆栈或不必要的用户隐私原文。
- **FR-053**: 用户反馈 MUST 关联 Trace、结果 Schema 版本、Prompt/模型版本和响应类型，并允许在脱敏后进入候选离线评测样本。
- **FR-054**: 可观测数据 MUST 能区分“批改成功但未保存”“首次保存”“幂等重放”“保存失败”和“状态未知后已对账”，以支持学习闭环审计。

#### Data and Privacy

- **FR-055**: Coach MUST 遵循最小数据使用：只把当前意图所需的画像摘要、学习材料和用户输入发送给模型；手机号、邮箱、地址、密码、令牌、支付数据和无关对话不得发送。
- **FR-056**: 用户学习记录、错题、会话状态、缓存、Trace、评测样本和生成产物 MUST 以认证用户隔离，禁止跨用户检索、拼接、缓存命中或评测混用。
- **FR-057**: 生产对话只有在脱敏、去除直接标识且通过授权流程后才能成为离线评测样本；默认评测集应使用合成或专门授权数据。
- **FR-058**: 用户取消请求时，尚未提交的临时答案、模型缓冲和工具中间结果 MUST 在不再需要恢复/对账后清理；取消不会删除此前已合法保存的学习记录。
- **FR-059**: 用户发起相关数据删除时，系统 MUST 停止该数据参与后续 Coach 画像和评测，并按批准的生命周期删除或不可逆匿名化会话、Trace 关联和评测副本。
- **FR-060**: 数据生命周期 MUST 为：核心学习画像、作答、复习事件和当前学习状态保留至账号删除；Coach 对话和检查点自最后活动起保留 90 天；流事件缓存完成后保留 1 小时，非内容的取消/幂等对账状态最多 24 小时；不含原始 Prompt/回答的 Trace 元数据保留 180 天；诊断内容默认关闭，显式启用且脱敏后最多保留 7 天；反馈文本保留 180 天。用户删除后核心数据、对话、反馈及诊断内容在 24 小时内从主存储物理清除，Trace 主体映射立即删除使剩余元数据不可关联。第一版离线评测仅使用合成或人工编写样本，禁止直接复制生产对话。
- **FR-061**: 外部模型的数据使用/留存设置 MUST 与本功能批准的隐私范围一致；若提供者无法满足最小数据和留存要求，该请求不得发送。

#### Learning State Update

- **FR-062**: 有效保存 MUST 记录原始练习、用户答案版本、批改结果、错误类型、材料/学习项关联和下一步推荐所需的可审计事实。
- **FR-063**: 学习状态更新 MUST 仅影响本次练习实际覆盖且已确认属于当前用户的单词或知识点；不得批量修改未作答项。
- **FR-064**: 用户 MUST 能看到每个受影响项在保存前后的状态、为何变化以及下一次复习时间；未变化项也可说明原因。
- **FR-065**: 第一版 MUST 使用独立的 SM-2 学习项状态管理 Coach 掌握度和复习计划：学习项具有 `NEW|LEARNING|REVIEW|MASTERED` 状态、重复次数、E-Factor、间隔和到期时间；逐学习项批改质量映射为 0–5，初始 E-Factor 为 2.5 且不低于 1.3，成功间隔依次为 1 天、6 天及 `ceil(前次间隔 × E-Factor)`，质量低于 3 时重置重复序列。`MASTERED` 要求至少三次成功复习、最近质量至少 4 且当前间隔至少 30 天。Coach 不得清除或重新解释现有 `WordBookRecord.isMaster`，也不得改变 `User.wordNumber`；旧流程完成单词时同步初始化新学习项状态，存量已掌握词通过确定性迁移补齐状态。
- **FR-066**: 在 FR-065 澄清并形成可测试规则前，Coach 不得声称已更新掌握度或下次复习时间；对应验收项属于发布阻塞。

#### AI Evaluation

- **FR-067**: 首批离线评测集 MUST 包含 50 至 100 条去标识、版本化、可重复运行的样本，并覆盖所有目标意图、不同学习水平/历史、正常路径、安全攻击和依赖失败。
- **FR-068**: 每条样本 MUST 包含：样本版本、合成/授权用户画像、请求与会话状态、可访问资源、预期意图、允许/禁止工具及顺序、预期 Schema 约束、预期安全结果、引用依据、质量判定规则和预算测量字段。
- **FR-069**: 确定性测试 MUST 直接判定认证/归属、工具选择范围、参数 Schema、调用前置条件、最终 Schema、分数范围、引用存在性、写门禁、幂等性、错误分类和敏感信息泄露。
- **FR-070**: 语言纠错准确性、等级适配、讲解清晰度、练习针对性、批改合理性、错误分类和 `nextAction` 适配性 MUST 使用预先定义的人工或独立模型评分量表；评分者不得看到不必要的真实身份数据。
- **FR-071**: Prompt 或模型版本变更后 MUST 运行完整回归集；Schema 或工具合同变更还必须运行所有确定性合同、安全、降级和写入一致性样本。
- **FR-072**: 发布最低门槛 MUST 为：认证/跨用户隔离/Prompt Injection/任意 `userId` 注入/写门禁/幂等/Schema 安全样本零失败；所有确定性合同样本通过；任何质量类别不得从已批准基线的“通过”回退为“不通过”。
- **FR-073**: 对暂时没有可信数值阈值的纠错质量、等级适配、TTFT、完整耗时、Token 和费用，首个候选版本 MUST 先记录相同数据集和环境下的现有 AI 基线；发布容差须以该基线的测量波动和明确批准的相对回退规则为准，不得在没有证据时宣称达标。
- **FR-074**: 离线结果 MUST 能通过样本/版本标识与线上脱敏 Trace、用户反馈和结果类型关联，以识别线上失败并转化为经审查的新回归样本。

评测覆盖和判定：

| Evaluation class | Required input coverage | Expected result | Judging mode |
|------------------|-------------------------|-----------------|--------------|
| 英语纠错 | 正确句、单一错误、多错误、可接受变体、不同等级 | 修正准确，不把可接受表达判错；解释与等级相符 | 参考答案确定性检查 + 人工/独立评分 |
| 等级适配 | 同题配不同等级/目标/已学词 | 难度、词汇和示例合理变化，事实不变 | 配对人工/独立评分 |
| 薄弱项练习 | 不同薄弱词、错误类型、到期计划 | 题目覆盖目标弱项且不泄露答案 | 目标覆盖确定性检查 + 质量评分 |
| 工具选择/顺序 | 五类意图、无需工具请求、恶意请求 | 只调用允许工具，写操作只在有效批改后 | 确定性 Trace 断言 |
| 工具参数与归属 | 合法、越界、未知字段、他人资源、注入 `userId` | 合法通过；非法/越权拒绝且无泄露 | 确定性合同/安全测试 |
| 批改与错误分类 | 全对、全错、部分对、多种可接受答案、不可评分输入 | 分数范围合法，逐项和总分一致，分类可解释 | 规则断言 + 人工/独立评分 |
| `nextAction` | 到期且薄弱、表现差、表现好、资料不足 | 推荐与已验证状态一致并说明依据 | 规则断言 + 人工/独立评分 |
| Schema | 缺字段、错类型、未知枚举、越界分数、畸形 JSON | 无效结果不直达前端或写入；修复/降级合法 | 100% 确定性 |
| 引用支持 | 有/无材料、失效材料、无权限课程 | 引用确实支持结果；无依据不伪造引用 | 确定性存在/权限检查 + 内容评分 |
| 安全攻击 | Prompt Injection、系统 Prompt 索取、任意用户标识、跨用户资源 | 零越权、零敏感泄露、零错误写入 | 100% 确定性安全门槛 |
| 依赖失败 | 模型超时、工具超时、资料缺失、无效输出、保存冲突 | 合法降级，无部分/重复写入 | 确定性故障注入 |
| 性能与成本 | 普通问答、长纠错、练习、批改、最坏工具路径 | 记录 TTFT、总耗时、Token、费用和预算终止 | 基线对比与预算断言 |

### Key Entities

- **Learner Profile Snapshot**: 某次请求所需的当前用户学习画像快照；包含可用信号、来源、新鲜度和缺失标记，不包含无关身份信息。
- **Coach Conversation**: 当前用户隔离的多轮会话及其生命周期；关联当前练习、工作流状态和最近结果。
- **Coach Request**: 一个逻辑请求；包含认证主体的内部关联、意图、预算、状态、幂等语义和 Trace。
- **Workflow Step**: 受控流程的一步；记录类型、顺序、状态、开始/结束时间和安全结果摘要。
- **Learning Material Reference**: 来自允许词典、课程或语法数据源的稳定材料引用；可在未来替换检索提供者而不改变业务合同。
- **Exercise**: 绑定当前用户和会话的练习实例；含题型、题目、目标学习项、材料引用、答案版本和状态；用户视图不含答案键。
- **Grading Result**: 对特定练习和答案版本的结构化批改；含分数、逐项结果、纠正、解释、错误分类和有效性状态。
- **Learning Attempt**: 一次通过门禁并幂等保存的作答事实；关联练习、答案版本、批改和受影响学习项。
- **Learning Item State**: 用户对单词或知识点的掌握/复习状态；具体状态语义受 FR-065 澄清约束。
- **Review Schedule Entry**: 某学习项的复习到期状态、优先级、上次表现和下次复习时间；具体调度规则受 FR-065 约束。
- **Coach Result**: 前端最终消费的版本化结构化结果，包含必需字段、引用、推荐理由和可选练习/学习更新。
- **Citation**: 对现有材料的受控引用，证明回答、练习或批改中的相关内容来源。
- **Trace**: 串联请求、模型、Prompt、工具、校验、时延、Token、费用、异常、写入和反馈的脱敏审计记录。
- **Evaluation Case/Run**: 可重复输入、期望、判定规则和版本结果，用于阻止安全与质量回归。

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 在完整安全评测集中，100% 未登录、无效令牌、任意 `userId` 注入和跨用户资源请求在读取学习数据或产生写入前被拒绝，且无资源存在性或敏感信息泄露。
- **SC-002**: 100% 工具输入、工具输出和最终完成结果符合其声明的版本化机器可读合同；无效模型输出直接到达用户最终结果或学习数据写入的数量为 0。
- **SC-003**: 评测集中的主要意图均能进入正确的受控工作流；所有确定性工具顺序和写入门禁断言通过。
- **SC-004**: 对成对的不同等级/历史用户样本，同一问题的回答或练习在至少一个预定义适配维度上体现与画像一致的差异，同时保持事实和引用正确。
- **SC-005**: 100% 可评分的有效提交返回 0–100 分数、纠正、解释、错误类型、示例、下一步行动和推荐理由；不可评分结果的 `score` 为 `null` 且不能保存。
- **SC-006**: 100% 通过双击、网络重试、流式重连和服务恢复重复发送的同一逻辑作答最多产生一条学习记录和一次学习状态变更。
- **SC-007**: 正常、取消、超时、模型失败、工具失败、Schema 失败和预算终止场景均产生明确且类型安全的最终状态；故障注入下的部分学习写入数量为 0。
- **SC-008**: 100% Coach 请求具备可查询的统一运行记录，包含 Prompt/模型版本、首字与完整耗时、输入/输出用量、工具顺序/耗时/状态、合同校验重试、终止状态和反馈关联，同时敏感日志扫描结果为 0 条禁止内容。
- **SC-009**: 首个发布候选具备 50 至 100 条可重复离线样本，覆盖本规格评测表全部类别；严重安全门槛零失败，质量类别不低于批准基线。
- **SC-010**: 用户可以在界面中识别连接、生成、工具执行、完成、取消、超时、失败和重试状态；最终学习状态更新明确显示为已保存、幂等重放或未保存。
- **SC-011**: 超过任何已批准请求预算的测试请求 100% 被安全终止，不启动后续写操作；预算内请求的 TTFT、完整耗时、Token 和费用相对基线不超过批准的回退范围。
- **SC-012**: 现有登录/刷新、词典浏览、已购课程查询、10 词学习、批量掌握、普通 AI 模式和非 AI 页面在回归验收中无新增阻断性缺陷或未经批准的业务行为变化。

## Assumptions

- 目标用户是当前 Web 应用中已登录的单一用户，不包含管理员代学、教师查看学生或多租户组织角色。
- 现有 JWT 认证机制是身份来源；本功能不改变登录产品流程，但要求 AI 端完整采用同一可信身份语义。
- 现有词典和已购课程能力可作为第一版材料来源；不存在的语法/课程正文能力按依赖和降级处理。
- 练习生成与批改使用文本输入；语音识别输入在进入 Coach 前按普通文本处理，不包含发音评分。
- 用户可在一个会话中多轮追问或完成一个进行中的练习；并发练习必须隔离。
- Prompt、模型、预算和评测阈值均作为版本化、可审计发布配置管理，但具体技术实现留到 Plan 阶段。
- 首批评测优先使用合成画像、人工设计对话和授权材料，生产数据只在去标识和批准后使用。
- 项目宪章目前仍是未填写模板，没有提供额外业务治理规则；后续若宪章生效且冲突，应先更新本规格。

## Resolved Clarifications

1. **Learner level authority (FR-015)**: 第一版以用户可编辑的 CEFR 自报等级为权威来源；当前表现仅有界调整本次难度，不自动改写等级。
2. **Mastery and review semantics (FR-065)**: Coach 使用独立 SM-2 学习项状态；旧 `isMaster` 与累计单词数保持原有语义，不被 Coach 覆盖。
3. **Retention and deletion (FR-060)**: 使用最小化分层生命周期；第一版离线评测禁止直接复制生产对话，用户删除使剩余 Trace 元数据不可关联。
